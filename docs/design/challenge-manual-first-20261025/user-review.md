# 供你审核：人工优先验证方案

对应详细设计：proposal v0.3。两位独立Agent各完成两轮审核，最终均PASS，现交你审核。此次只设计，没有编码或改动生产。

## 你会看到的流程

1. 系统检测到挑战，当前控制台自动展示账号和真实验证画面；操作的是服务器原浏览器，保持原登录会话。
2. 画面已显示且可以操作后，开始5秒倒计时。点击“我来验证”或直接按下滑块可以接管；无人接管才自动尝试。
3. 接管后给30秒独占人工时间，自动程序暂停。完成验证后系统自动检查结果，无需靠“我完成了”按钮声明成功。
4. 30秒到期或你选择交给系统时，先收回输入并等待已提交答案的结果；你刚提交的答案若成功，直接继续连接检查，不再启动自动拖动。
5. 仍需操作且允许自动时，系统使用同一页面自动尝试。自动正在拖动时，你可以预约下个安全边界人工接管。
6. 页面分别展示“验证通过”“部分来源仍待确认”“登录成功”“账号连接已恢复”，不会把滑块通过当作最终恢复。

## 建议默认值与取舍

| 事项 | 建议行为 |
| --- | --- |
| 人工优先 | 可操作首帧出现后5秒；从服务端计时，不是从检测到风险时开始 |
| 人工操作 | 接管后30秒，不因移动鼠标或刷新续期 |
| 人工答案等待 | 到期或交接后，最多观察10秒未决结果；仍不明确就保留风险，停止本轮 |
| 无人在线 | 发现窗口2秒内没有可用前台页面，直接自动；有前台但画面8秒内未准备好，也按模式自动或待人工 |
| 断网/转后台 | 停止输入，最多3秒恢复宽限；恢复不重置30秒；不让人工与自动同时操作 |
| 多账号同时挑战 | 一次展示一个；已有人工操作时，其余账号若8秒内没有展示位，可能自动尝试，队列提前提示 |
| “我来重试” | 新一轮默认只人工，准备好后给30秒；不悄悄转自动。你明确按“交给系统”才允许自动 |
| 自动次数 | 每轮总计最多3次自动手势；同账号15分钟最多3轮，达到上限后等人工，避免无限重试 |
| 支持范围 | 先支持滑块/点击；短信、人脸、外部App确认等提示其他验证方式/重新授权 |
| 入口范围 | 账号运行中的挑战及扫码登录过程中的挑战都纳入；扫码弹窗内直接切到验证画面 |

## 账号状态如何变化

只有业务身份、凭证保存、适用IM注册和新鲜心跳都满足，且没有剩余验证风险时，才显示“账号连接已恢复”。仅部分来源恢复时，显示哪些已恢复、哪些仍待确认，账号仍可保留“需要验证”。

验证成功不自动重发发货、改价、发布、发消息等原操作；这些操作需要回原页面核对真实结果，再按原流程提交。系统会给出明确提示。

## 独立审核与实施门槛

首轮两位独立Agent提出14项P1/P2问题，主Agent修订后由原审核者逐项复审，14项均VERIFIED/CLOSED，最终设计PASS，无开放P0–P2设计问题。原始记录见review-log.md、review-product-r2.md与review-architecture-r2.md。

设计批准后先做隔离技术验证，确认原页面裁剪、手机触控、跨域iframe、画面延迟和输入实用性，再实现业务链路。当前没有证据证明新画面流已经可用，设计审核不等于上线验收。

你要审核的是以上产品行为与详细方案。尤其请留意30秒人工窗口、多账号繁忙时转自动、“我来重试”只人工、自动次数上限这四项新增规则；如需调整，可直接指出具体参数或交互。收到你的审核意见前，本任务停留在设计阶段。
