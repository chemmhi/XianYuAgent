## 接口、参数与状态的审计口径

正常业务接口必须分别记录以下字段，不能只留下“HTTP 200”：

| 边界 | 应核验的输入/参数 | 输出与副作用 |
| --- | --- | --- |
| 应用会话/账号查询 | 请求方法、账号范围、请求时间、身份授权边界 | 实际账号 ID、业务状态、风险状态、连接状态 |
| 平台 Token 获取 | 请求时间、API 名称/版本、设备标识、请求体与响应关联 ID、Cookie 版本 | 平台业务结果、Token 是否实际产生、有效期字段、Cookie 变更；HTTP 成功不能代替平台成功 |
| 平台登录态检查 | 同一账号与凭证版本、调用时间 | 平台业务成功及实际 userId；必须与目标身份一致 |
| IM WebSocket | 连接 URL、消息关联标识、注册使用的设备与会话版本 | 真实注册响应、客户端连接事件、后续断连与错误；临时进程与常驻服务必须区分 |
| 应用凭证保存 | 账号/所有者范围、完整 Cookie 快照、版本与写入时刻 | 不得以空快照覆盖仍有效数据；本次未执行凭证保存 |
| 风险核销 | 风险来源、发生时间、真实业务成功时间 | 只允许真实成功驱动相应旧风险的核销；不得强制伪造 connected |

## 已知工程问题与结论限制

1. Cookie 快照为空、旧快照和响应增量合并时，存在完整凭证被不完整集合覆盖的历史问题。身份、域、路径、有效期及分区属性属于会话数据完整性，不能只保留扁平字符串。
2. 浏览器业务调用和服务器 HTTP 调用曾出现不同结果。后续服务器 HTTP Token 获取仍要求验证；不能因为已有一次可用 Token 就宣称生产续期能力已修复。
3. 采集动作会影响运行；失效元素观测曾阻塞。记录器错误必须单列，不能混同平台业务失败或掩盖被中断流程。
4. 原始记录报告相关 API 回归 29 项、诊断契约 13 项、API 编译等通过。这些是历史验证，不是本次重新运行，也不代表正式业务 E2E。
5. 存在响应正文缺失、中断观测、部分启动器版本缺口、未冻结的远端状态和时效性凭证。可以定位历史证据，**不能保证未来 1:1 得到相同平台响应**。
6. 没有验证部署后常驻服务自动完成新挑战，没有验证长期续期，没有验证生产控制台恢复；总体验收仍未通过。
