# 检测安全验证后立即恢复（2026-10-24）

此前仅记录需要验证的账号状态，已有 IM Token 可继续连接；启动和业务请求检测到风险后，可能一直等到十分钟凭证续期才恢复。本次补上风险事件与恢复执行器之间的调度。

## 最终行为

- API 的 MTOP/IM 检测到验证风险后，先保存风险，再异步唤醒账号恢复。原业务请求按原错误语义返回，不等待浏览器挑战，也不重发业务消息。
- 启动读取到已有验证风险时，在新建 IM 客户端前取得新凭证；已有客户端的风险也立即调度恢复，十分钟定时器仍用于常规续期。
- worker 通过现有 Redis 依赖通知 API，浏览器只由 API 持有。通知仅包含管理员、账号和风险来源，无凭证或挑战 URL。
- 数据库风险为事实来源。API 启动和 Redis 恢复订阅后重新检查已登录账号，补处理未收到通知的风险。
- 账号内的恢复任务、Token 请求和连接启动共享正在执行的任务。递归风险通知不重复打开浏览器；失败保留短冷却，新信号在冷却中到达时，登记一次到期重试，无需等待十分钟定时器。
- 验证成功后的原生凭证保存、账号身份检查和分区 Cookie 快照逻辑沿用既有实现。外部接口来源的风险仍由对应来源的成功证明核销，不直接伪造账号健康状态。
