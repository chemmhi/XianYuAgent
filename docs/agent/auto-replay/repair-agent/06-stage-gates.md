# 阶段门禁与完成定义

## 阶段状态

PENDING → IN_PROGRESS → PASS；失败进入 FAIL，环境或外部依赖阻塞进入 BLOCKED。只有当前阶段所有适用门禁和必需评审为 PASS，才能进入下一阶段。

## 阶段映射

| 阶段 | 主要产物 | 通过门禁 |
| --- | --- | --- |
| 0 | AR-VS-00 范围与策略锁定 | 业务规则、敏感边界、验收指标无歧义 |
| 1 | AR-VS-01 架构与模块边界 | 职责、数据所有权、同步/异步边界清晰 |
| 2 | AR-VS-01 数据/API 契约 | 字段、错误、幂等、并发、脱敏、审计和回滚明确 |
| 3 | Agent Dynamics 可观测面 | 状态、错误、加载、空态、权限和结果可展示 |
| 4 | AR-VS-02 至 AR-VS-08 编排 | 每个切片具备输入、输出、非目标、证据和回滚 |
| 5 / 5.5 | 单切片实现与提交 | 测试、评审、中文 Conventional Commit 和差异卫生通过 |
| 6 | AR-VS-08 集成 | 真实入口到持久化与状态回读通过 |
| 7 | 安全、性能、可观测性、发布准备 | 无未接受 P0/P1，告警、恢复和回滚可演练 |
| 8 | AR-VS-09 发布、回滚、交接 | 灰度、兼容、回滚、发布后冒烟和交接通过 |

## 固定阶段卡片

开始前必须写明：目标、输入、输出、禁止范围、假设、验收、门禁、评审轮次、证据位置和回滚方式。

## 统一 DoD

- 用户行为、输入、输出、禁止范围和假设已写入切片卡；
- 数据库、后端、API、前端、消息和第三方适配边界明确；
- 正常、失败、未登录、无权限、空数据、重复请求和关键并发有测试；
- 迁移、配置、日志、指标、事件、文档和回滚同步；
- 适用类型检查、构建、单元、集成、E2E、视觉检查真实执行；
- 默认完成业务/验收、架构/数据流、质量/安全/运维三轮独立评审；
- 问题按 OPEN → FIXING → READY_FOR_REVIEW → VERIFIED → CLOSED 闭环；
- P0/P1/P2 全部关闭后才能标记切片 PASS；
- 提交哈希、验证命令、评审轮次和剩余风险可追溯。

## 评审最小集

1. 业务/验收：流程、边界、用户可见行为和成功标准；
2. 架构/数据流：模块边界、状态、接口、一致性和依赖方向；
3. 质量/安全/运维：测试、权限、敏感信息、性能、日志、监控、发布和回滚。

存在前端可见变更时增加视觉评审。无法执行的检查必须记录原因和替代证据，不能宣称整体完成。
